# FieldOps AI — Design Context

## Design Context

### Users

**Two equally-important primary users:**

1. **Field supervisor / foreman on a phone or tablet, on a jobsite.** Outdoors, in direct sunlight half the day, often wearing gloves, often on bad LTE. Wants to check in on workers, approve timecards, look at a photo, file an alert — fast — and put the phone back in a pocket. Will abandon any interface that requires more than two taps to answer "is my crew where they should be?"
2. **Back-office ops manager at a desk.** Indoor, large monitor, mouse + keyboard, runs payroll, pulls reports, manages cost codes and PTO. Tolerates density and tables. Needs export, filter, bulk-edit, audit trails.

A third tier exists — the owner / executive doing weekly check-ins — but they're not the design driver. Designing well for the two primaries will serve them.

**Job-to-be-done**: Produce GPS-verified, tamper-proof, timestamped evidence of who worked where, when, and on what — and make that evidence actionable (payroll, billing, dispute resolution, compliance). The product primitive is **proof**.

### Brand Personality

**Three words: trustworthy, serious, proof-grade.**

Closest reference points: **Stripe Dashboard**, **Linear**, **Mercury**. Not because field ops is fintech, but because those interfaces share the same DNA — restraint, precision, exact typography, color used sparingly and meaningfully, density without crowding, motion that signals state rather than decorating it.

Emotional goals:
- A supervisor opens the app and immediately trusts what they see.
- An owner glances at the dashboard and feels their money is being tracked carefully.
- A worker sees their own data and feels respected, not surveilled.
- A judge or auditor, in a dispute, looks at the timeline and accepts it as evidence.

The interface should feel like a **legal document that happens to be a web app** — calm, exact, no decoration, every element earning its place.

### Aesthetic Direction

**Theme**: Light mode is primary (sunlight readability for jobsite use). Dark mode is supported for office desk use but never the showcase. Pure black and pure white are forbidden — always tinted.

**Color philosophy**: Mostly neutral (warm-tinted stone/slate), with semantic color reserved for meaning: emerald for verified/good, amber for warning/needs-attention, red for danger/violation, blue only for active/in-progress state. No decorative gradients. No glow effects. No glassmorphism. Tint neutrals slightly toward a brand hue for subconscious cohesion.

**Typography**: Geist is acceptable as a system-grade workhorse — but the brand needs a *display* voice for headings, big numbers, and key labels. Body should remain neutral. Tabular numerals everywhere monetary, time, or quantity values appear (this is non-negotiable for a proof-grade product).

**Layout**: Generous whitespace by default; tables and dense data views earn their density. Left-aligned text. Asymmetric layouts over centered everything. Cards are not the default container — use them when grouping genuinely benefits comprehension, otherwise let the page breathe.

**Anti-references — what this must NOT look like:**

- **Generic AI/SaaS**: No purple→blue gradients, no glowing dark mode, no cyan-on-navy, no glassmorphism, no gradient text on metrics. If a stranger could mistake it for ChatGPT's marketing page, it has failed.
- **Legacy enterprise (Procore / ServiceTitan / BuilderTrend)**: No crowded toolbars, no gray-on-gray, no 1990s data-table chrome, no nested tabs-inside-tabs. Workers refuse to use these. We are the alternative.
- **Consumer-cute (Notion stickers / pastels / emoji)**: No emoji in product chrome. No soft pink. No "✨ Magic ✨" microcopy. Owners need to trust this with payroll.
- **Brutalist / experimental**: No monospace-as-personality. No raw HTML aesthetic. No intentional ugliness. Coolness is not the goal; trust is.

**The single thing someone should remember**: "It felt like the interface knew exactly what mattered and didn't waste my time."

### Accessibility & Inclusion

**Hard constraints:**

- **WCAG 2.2 AA across all surfaces** — this is a contract/legal requirement, not aspirational. Color contrast, focus indicators, keyboard navigation, ARIA roles, no contrast violations.
- **Sunlight readability**: All primary content (worker names, timestamps, statuses, numbers) must clear AAA contrast (7:1) on the light theme. No thin gray text on white. No gray-400 body. No low-contrast placeholder text used as a value.
- **Low-bandwidth / offline-tolerant**: Skeletons over spinners. Optimistic UI for common actions. Clear offline banners. Cached data shown with a "last updated" stamp instead of being hidden.
- **Touch targets** (mobile): 44pt minimum, 56pt for primary actions. No icon-only critical actions on small screens.

**Soft constraints:**

- Reduced-motion respected for all transitions.
- Color-blind safe: never communicate state with color alone — pair with icon, label, or position.
- Tabular numerals for all numeric data so columns align.

### Design Principles

1. **Proof is the product.** Every screen should make the user feel that what they're looking at is verifiable, attributable, and defensible. Show GPS, timestamps, who-changed-what, and source-of-truth indicators by default — not buried in a detail view.
2. **Sunlight beats moonlight.** Light theme is the design target. If it can't be read on an iPhone in 2 PM Arizona sun, it doesn't ship. Dark mode is an accommodation, not a showcase.
3. **Density earns its keep.** Use whitespace generously on overview screens; use density unapologetically on payroll, timecards, and reports — those users want a spreadsheet, not a feed.
4. **Color is a sentence, not a paint job.** Each accent color must mean something. If green doesn't reliably mean "verified," it shouldn't be green.
5. **Two taps or two clicks.** The primary jobs-to-be-done ("is my crew on site?", "approve this timecard", "open this photo's proof") should never take more than two interactions from the dashboard.
6. **No decoration that costs trust.** Skip the gradient. Skip the icon-over-every-heading. Skip the hero metric template. Anything that makes this look like a marketing landing page makes it look less like proof.
